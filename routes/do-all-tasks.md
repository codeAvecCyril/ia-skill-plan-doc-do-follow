# do/all-tasks E{n} F{n} — Execute All Feature Tasks

**Purpose**: execute all feature tasks in dependency-ordered waves of **feature-coder** subagents — one coder per **lane** (chain of sequential tasks) or solo task — run by **feature-coordinator**, then verify inline — no separate `do/verify` pass

**Mindset**: adopt `subagents/feature-coordinator.md` in full — principal = coordinator: owns plan fidelity, code quality, live Task Summary, user feedback · reasoning-class model recommended for principal; coders run standard model, medium thinking

**Inputs**: `feat-tasks.md` · `subagents/feature-coordinator.md` · `subagents/feature-coder.md` · repository instruction file(s) (SKILL.md → Platform integration) · `routes/do-verify.md` for final phase · `routes/plan-redesign.md` only on design gap

**Outputs**: implemented code and tests · Task Summary updated after **each** task · progress report after each wave · feature 🟢 (or 🔵 with gap list) · statuses cascaded via Status Sync

## Steps

1. **Preflight**: `pddf lint-tasks E{n} F{n}` (FAIL → triage: local defect = fix-packet, contradiction = redesign · WARN only = proceed; pre-3.7 tasks without Story Trace run as planned, story walk at verification uses PRD acceptance criteria) · `pddf waves E{n} F{n}` (waves + lanes; no Lane column = every task solo) · read Story Trace, Shared Contracts, Design Gaps via `pddf section` — never Task Details · open gap → stop, handoff `plan/redesign E{n} F{n}` · resume-safe: skip 🟢 rows, re-dispatch 🔵 rows whose work is absent · post one line: `{n} tasks · {l} lanes · {w} waves · critical path {…}`
2. **Dispatch wave**: every solo task and every lane whose next pending task is ready · `pddf task … 🔵` (first call writes Execution line with `--wave`) · one feature-coder per solo task or lane (coordinator → Lane dispatch: continue mode where platform can message a finished subagent, else batch mode) · brief = identical head (Tooling one-liner, "obey `feature-coder` rules") + tail `Run: pddf packet E{n} F{n} T{n} — its output is your whole task packet` (batch: `… L{n}`) — packet by reference, never retyped · coder without shell → paste `pddf packet` output · never PRD, architecture, or whole tasks file
3. **Accept each task as it returns** (coordinator → Acceptance — per task, lanes included): accepted → `pddf task … 🟢 --wave k/w --eta {eta}` immediately → continue mode: send lane's next packet to same coder · rejected → re-dispatch with concrete feedback (retry 2 on escalated tier) · escalation → coordinator → Escalation triage · DEFECT from Test task → reopen producer (coordinator → Acceptance). Coder questions never reach user
   - **While coders run**: coordinator → Watchdog (`pddf beat E{n} F{n}` first) — over-budget or looping coder → clean STOP → HANDOVER → one re-dispatch on escalated tier · long test run announced by a beat ≠ stuck
4. **Close wave** (all tasks of wave 🟢 — lanes keep running across waves): run linter/formatter + typecheck/build once over wave's files; fix integration breaks · never re-run tests coders already ran green — Test tasks and verification own testing · `pddf sync` · progress report (coordinator → Reports) · continue straight to next wave — never ask "continue?"
5. Sequential tasks without a lane (final integration tests, ordered migrations): dispatch singly, or implement inline under `subagents/feature-coder.md` discipline
6. **Design gap** (triage verdict `redesign`): stop dispatching tasks that depend on the gap; let independent in-flight tasks finish and accept them · gap recorded in Design Gaps · run `plan/redesign E{n} F{n}`: inline if principal is reasoning-class (load route, re-read PRD/architecture/tasks fresh — set execution context aside), else stop with handoff `plan/redesign E{n} F{n}` on a strong model · after redesign, resume at step 1
7. **Verification phase** — all tasks 🟢: run gates of `routes/do-verify.md` inline, incl. Story walk (conditional subagents where triggers fire; inline-first for small surfaces). All pass → feature 🟢, remove Execution line; any fail → 🔵 with each gap as complete sentence
8. Run Status Sync. Changelog per hard rule: one feature-verified 🟢 line in epic changelog (project changelog only on epic completion) — never waves, gates, or task details · final report (coordinator → Reports) · Handoff: `plan/feat E{n} F{n+1}`, `plan/epic E{n+1}` if epic done, or gap list with recommended fixing route
